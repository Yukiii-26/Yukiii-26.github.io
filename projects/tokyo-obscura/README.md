# 東京暗箱 / Tokyo Obscura

零美术、文字驱动、地图为现场的地点推理游戏。当前版本 **v0.3 · 全十二章**，纯静态网页：**双击 `index.html` 就能玩**，不需要服务器、不需要构建、没有 CDN 依赖（地图瓦片走日本国土地理院，需要网络）。

---

## 一、游戏怎么玩

1. **主界面**：开始游戏 / 继续游戏 / 加载游戏 / 章节选择 / 基本介绍 / 返回主页（本站版本里指向个人主页 `../../index.html`）
2. **读卷宗**：左栏是材料卡（现场简报、尸检摘要、影像卡、档案、证词）。点标题展开/收起
3. **钉疑点**：带 ◇ 的行都能点。觉得不对就点一下 → 钉成「疑点」
4. **做对照**：状态条「疑点」→ 选一条疑点 → 选**另一份材料**。对上了生成一条「矛盾」
5. **去定位**：状态条「影像定位」→ 地图上点/拖图钉到机位 → 转罗盘定镜头朝向 → 确认
6. **结案**：矛盾够了、位置准了，「结案陈词」亮起 → 指认 + 出示证据 → 受理/退件
7. 受理后可「继续 · 案 0X」进入下一案；案 12 结案后出现 `FIN · 全剧终`

判定规则：距离 ≤ `goodRadius`（150–170m）、朝向误差 ≤ `headingTolerance`（50–55°）；`nearRadius` 内会给出「很近，再调朝向我们」的提示。`need` 字段决定需要的矛盾条数（2 或 3）。

## 二、存档与章节选择

- 存档写在**浏览者自己的浏览器**（localStorage，键 `tokyo-obscura.save.v1`），不上传服务器，纯静态站即可用
- 4 个槽位：`auto`（自动存档）+ `s1` / `s2` / `s3`（手动槽）
- 「继续游戏」= 读最新的那个档；「加载游戏」= 手动选槽；新游戏选已有存档的槽会二次确认
- 推理过程自动写当前槽（每步操作后保存）
- **章节选择**：主界面第三屏入口，按章节列出全部 12 案，从任意一案直接开始（写入自动存档）。换设备 / 换浏览器 / 清缓存丢档时的兜底通道
- **限制**：换浏览器/换设备/清缓存/无痕窗口仍会丢档（localStorage 本身如此）

## 三、提示按钮与深色模式

**提示**：游戏页标题行右侧有个「提示」小按钮。点开是「本案怎么结」——先讲清五步流程（读卷宗 / 钉疑点 / 做对照 / 去定位 / 结案），每步带本案的实时进度；下面「还剩的方向」按还没解出的矛盾，逐条给出「把「A 卡」里的某一行，拿去和「B 卡」对照」这类指向性提示，点「再给一条」逐条揭示。只指方向，不替玩家读文本。

**深色模式**：右上角圆钮切换（☾ / ☀）。

- 进入时**默认跟随系统**（`prefers-color-scheme`），网页不写任何设置
- 手动切换过一次后，本次停留在你选的那一侧，不再跟随系统
- **刷新或重新进入即重置**，回到跟随系统 —— 深浅色不落盘、不写 localStorage，和存档完全无关

深色下地图瓦片整体反相降饱和（`invert(.9) hue-rotate(180deg)` + `brightness(.82)`），让地名仍是浅字深底，不刺眼也不糊。

## 四、字体

正文与标题用 **思源宋体**（Source Han Serif SC，与 Noto Serif SC 同源），字重 200–900 可变字体。

为了不依赖访客系统里装没装这个字体，仓库里放了一份**按游戏文案子集化**的 woff2（`vendor/fonts/TokyoSerif.woff2`，约 470KB，只含游戏里用到的 1200+ 字），CSS 里 `@font-face` 自托管，`--serif` 首选 `TokyoSerif`。数字、编号、英文小标签用系统等宽字体（`--mono`）。

> 改了文案 / 加了新案子后要重新生成子集，否则新字会回落到系统字体：`atlas-shots/mksubset.py`。

## 七、加一个新案子

在 `js/cases-10-12.js`（或新建文件并在 `index.html` 里多引一个 `<script>`）里往 `window.CASES` push 一个对象：

```js
{
  id: '13', chapter: '第X章 · 字', code: 'FILE 13',
  title: '案件名', place: '地名', date: '2031-06-01',
  victim: '死者 …',
  need: 2,                                  // 可选：需要的矛盾条数，默认全部
  map: { center: [35.69, 139.76], zoom: 16, bounds: [[35.68,139.74],[35.70,139.78]] },
  target: { lat: 35.6959, lng: 139.7581, heading: 292, goodRadius: 160, nearRadius: 600, headingTolerance: 50 },
  cards: [
    { id: 'brief', kind: 'brief', label: '现场简报', lines: [{ text: '…' }] },
    { id: 'photo', kind: 'photo', label: '影像卡 A-07', meta: '来源…', note: '…',
      diagram: window.FIG('<rect …/>', 'FIG.7 …'),
      lines: [{ id: 'p1', text: '…' }, { id: 'p2', text: '…' }] }
  ],
  rules: [ { id: 'x-1', suspect: 'p2', card: 'weather', title: '矛盾标题', body: '推理说明' } ],
  close: {
    prompt: '拍摄者是谁？',
    suspects: [ { id: 's-a', n: '选项一' }, { id: 's-b', n: '选项二' }, { id: 's-c', n: '选项三' } ],
    correctSuspect: 's-b',
    evidencePrompt: '哪一件材料最不像话？',
    goodEvidence: 'x-1',
    endingGood: '…', endingBad: '…'
  },
  outro: '…'                               // 可选：结案后的收束文字
}
```

- `kind` 决定卡片样式：`brief` / `autopsy` / `photo` / `archive` / `testimony`
- `lines[].id` 有 id 的行才可点选（会显示 ◇）
- `rules[].suspect` 必须是某张卡里存在的行 id
- **硬约束 1**：`rules[].card` 必须存在，且**不能与 `suspect` 所在的那张卡相同**（玩家是拿「这张卡的一行」去对「另一张卡」，同卡永远解不出）
- **硬约束 2**：`goodEvidence` 必须能在玩家实际解出的矛盾里出现——`need:2` 只能解出两对，关键证据要放在 `rules[0]` / `rules[1]`
- **硬约束 3**：结局文本里的换行用真实的 `\n`（不是 `\\n` 字面量）
- **叙事硬约束**：每条矛盾必须只靠读文本就能推出来

示意图 `window.FIG(inner, caption)`：600×200 的 SVG 外壳，`inner` 用局部坐标（内容被 `translate(85,0)` 居中，y 不要超过 175），右下角自动带图注。不做位图美术，一律线稿。

## 九、已知限制

- 没有章节过渡动画、没有音效、没有证据板连线（矛盾是列表）
- 存档只在本机浏览器（用「章节选择」兜底）
- 地图瓦片来自日本国土地理院，中国大陆访问速度一般
- 深浅色切换不记忆：刷新后回到跟随系统（按需求如此）
- 谜题强度靠文本；跳过「做对照」会被结案条件挡住
