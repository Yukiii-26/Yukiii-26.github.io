## 读取规则

- 改 CSS：**只读 `css/style.css`**，不要打开 `index.html`（它的 `<style>` 是空壳，样式全在 css 文件里）。
- 改案子内容：**只读对应的那一个 `cases-XX-XX.js`**，读 `.js` 里顶部的案件结构注释即可，不要读 `app.js`。
- 改玩法：读 `js/app.js`，它是 `(function(){ 'use strict'; ... })()` 包裹的单个 IIFE，按函数名 grep 定位，不要整读。
- 改存档：**只读 `js/save.js`**（69 行，全读也不贵）。存档体字段见文件头注释。
- ⚠️ **`vendor/` 一律不要读、不要改。**
- ⚠️ 这个作品**改样式必须同时改 `index.html` 里 `<link href="css/style.css?v=YYYYMMDDx">` 的版本号**，否则浏览器用旧缓存。
  （2026-11-01 踩过：`css/style.css?v=20261101b`）

## 这个作品的特殊约定

- **深浅色不参与全站统一**：它用 `prefers-color-scheme` 跟随系统，**不写 `localStorage.theme`、刷新即重置、`<html>` 上没有 `data-theme`**。
  这是用户明确要求保留的（原设计），**不要「统一」成别的页面那样**。
- 页面有 `favicon.png`（2026-11-01 加的），别的作品页多是内联 SVG data URI。
- 脚本按 **固定顺序** 加载：leaflet → cases-01-03 → cases-04-06 → cases-07-09 → cases-10-12 → save → app。
  **`app.js` 必须最后**，它读 `window.CASES` 和 `window.Save`。
- 存档 key 在 localStorage，改结构要写迁移逻辑，否则老存档读不出来。
